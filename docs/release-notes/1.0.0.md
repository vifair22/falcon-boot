Falcon-Boot 1.0 is the first release with a compatibility promise. From here on, a 1.x release won't break a stick, a station, a blessed image or a command you already use. Manual Section 14.4 says exactly what that covers, and what's outside it.

## Upgrading from 0.3

Nothing in 1.0 breaks what 0.3 made. Install the new package or tarball, then bring each stick and station up to it in place:

```sh
sudo falcon-boot-mkstick update /dev/sdX
```

`update` now also replaces your stick's signing appliance with this release's, signed with the stick's own key, and keeps the old one as `appliance-uki-prev.efi` so you can still boot it from the chooser. Pass `--keep-appliance` if you'd rather leave it alone.

## What's new

- **Windows XP installs from its ISO.** The BIOS stick now takes XP through text mode and the GUI phase to a desktop that boots with the stick removed. It's been installed to the desktop on a ThinkPad T430 as well as in the corpus, and on a stick plugged into USB as well as on IDE.
- **A late USB stick no longer strands Windows Setup.** If WinPE finds your stick only after winjump's 30-second search, which happened with Windows 7 on a T430, winjump keeps watching and attaches the ISO when the stick shows up.
- **One ESP holds a whole station.** On a disk with an EFI System Partition, the BIOS half of a station now lives in the ESP beside the UEFI half, the same way it does on a stick, so a machine with a full disk can have both. `station install --bios` or `--uefi` adds the missing half to a station that has the other. Older stations keep their station partition, and `update` still handles them.
- **One STATION.INI for a dual-mode station.** A BIOS station on an ESP reads its own `STATION.INI` when there is one, and the UEFI station's otherwise, so you can keep a single file.
- **`update` can replace shim.** `--replace-shim <dir>` swaps shim and MokManager, saving the old ones first, for a shim your firmware's SBAT level has revoked.
- **Signed checksums.** `SHA256SUMS` is signed with an offline release key, and Manual Section 14.1 shows how to check a download with `gpgv`.

## Fixed

- Bazzite and other images whose GRUB reads a different `grub.cfg` copy than the one their menu entry came from now boot through falcon-hook with Secure Boot on (D3B).
- The BIOS spinner no longer shows smileys and hearts on video BIOSes that ignore font loads, such as SeaVGABIOS under coreboot. It falls back to `| / - \`.
- A FreeBSD image too big for memory no longer advises pressing `c`, which can't help; the page says what does.

## Changed

- Windows 2000 install media is refused with an explanation. Its USB storage driver can't be made to load early enough, and it never installed under 0.3 either. Booting an installed Windows 2000 from its disk is unchanged.
- The release is proven before it's tagged: the merge into master builds the release and its packages, installs the tarball, and boots a stick made by the installed mkstick.

## Known limitations

- **Pressing `c` on a Linux or BSD live ISO under UEFI doesn't reach a desktop.** `c` starts the ISO's own loader, and the system it boots can't see the virtual CD once firmware hands over. Enter takes the routes that work. Earlier scorecards counted some of these as passing; that was a harness bug, fixed in this release.
- **Some USB sticks are slow through firmware drivers.** A Kingston DataTraveler Max takes about 70 ms for every 64 KiB read on AMI firmware and is slow on a T430's stock firmware too, while other sticks are fine on the same machines. Try another stick if a boot takes minutes. Manual Section 5.6 has the details.
- **Windows 7 and Vista under UEFI** haven't been validated in QEMU. They work from the BIOS stick.
- **Falcon-Jump's PC Card boot** is experimental and outside the compatibility promise.

The full scorecard is `docs/coverage.md`, and Manual Section 14 explains every file in this release.
