# falcon-boot static analysis baseline.
#
# ==========================================================================
# 0. Which toolchain this file answers to
# ==========================================================================
#
# binhost-builder's harness container, and only it. Decided 2026-09-20.
#
# The gate compares a run against this file, so the file is only meaningful
# next to a fixed set of analyzer versions. The container pins them
# (tools/coverage/Dockerfile: Debian trixie, cppcheck 2.17, clang-tidy LLVM
# 19, gcc 14), which is the same reason the corpus and `make test` moved
# there: a result nobody else can reproduce is not evidence. Regenerate with
#
#     tools/coverage/harness.sh -- tools/analyze.sh --update-baseline
#
# A run on a workstation will disagree, because its analyzers are newer and
# report a different set. That is expected and is not a reason to rewrite
# this file from one; the previous baseline was generated that way and held
# 28 entries against this run's 44, almost all of the difference being
# bugprone-narrowing-conversions that LLVM 22 no longer emits.
#
# One trap, recorded because it cost a cycle. tools/analyze.sh keeps test
# sources out of the gate by looking for the substring "/src/" in each
# absolute path from the compile database. The harness used to mount the
# tree at /src, so every path matched and the gate linted the whole test
# suite: 403 entries, 357 of them in tests/ and 131 of them clang parse
# errors rather than findings. The mount is /work now
# (tools/coverage/harness.sh) and the numbers below are what the gate was
# always meant to report.
#
# falcon-cli/src/sign/util.c fd-leak x3: gcc's analyzer has no model for exec, so
# each dup2 onto a standard descriptor in the forked child before execvp
# reads as a leak; the descriptor surviving the exec is the whole point.
# Identical pattern and rationale as the scoped pragma in
# falcon-cli/src/common/proc.c.
#
# Managed by tools/analyze.sh. Data lines below are tab separated:
#
#     stage <TAB> file <TAB> check-id <TAB> message
#
# with no line or column number, so an edit that only moves code around does
# not churn the file. Duplicate keys are kept, one line per occurrence, which
# means the *count* is part of the gate: a second hit of an already-baselined
# pattern in the same file is reported as new and has to be looked at.
#
# Regenerate with `tools/analyze.sh --update-baseline`. That preserves this
# comment block and nothing else, so every entry's reasoning belongs here.
#
# An entry here is a claim that a human looked at the finding and decided it
# does not describe a defect. Do not add one without reading the code.
#
# ==========================================================================
# 1. bugprone-implicit-widening-of-multiplication-result (21 entries)
# ==========================================================================
#
# The check stays enabled (see .clang-tidy) because it is the one that would
# catch a real offset overflow in the media parsers. Every current hit was
# audited and every one multiplies a bounded index by a small compile-time
# constant, in unsigned int, with no way to reach 2^32:
#
#   falcon-core/src/crypto/{aes,aesni,sha256,sha512}.c   19 entries. All `4u * i`,
#       `16u * r` and friends where the index is a loop counter bounded by a
#       literal (4, 8, 16, 64) or by nk <= 8. Fixed-size state arrays.
#
#   falcon-core/src/fs/exfat.c:503                    `2u * j`, j is a uint8_t bounded
#       by take, which is clamped to 15 two lines earlier.
#
#   falcon-core/src/fs/ext4.c:516,526,550              `i * EXT_ENT_SIZE`, EXT_ENT_SIZE
#       is 12 and i < entries. entries comes from a 16-bit on-disk field, so
#       it is at most 65535 and the product is at most 786420. The bound that
#       actually matters, entries against the buffer, is enforced by
#       extent_node_check, which every node passes through before it is
#       indexed (including the in-inode root, checked before the descent
#       loop).
#
#   falcon-efi/src/iso/iso.c:455,458                    `(DIR_SECURITY + 1u) * 8u` and
#       `DIR_SECURITY * 8u`. Both operands are literals.
#
#   falcon-core/src/luks/luks.c:121                      the operand is the macro
#       LUKS_MAX_HDR_SIZE, `(4u * 1024u * 1024u)`. A constant, compared
#       against a uint64_t.
#
# ==========================================================================
# 2. misc-use-internal-linkage, apps/stick/efi_main.c (1 entry)
# ==========================================================================
#
# `efi_main` has no declaration in a header and no in-tree caller, so the
# check concludes it can be static. It cannot: it is the PE entry point, named
# by `-Wl,-e efi_main` in LDFLAGS and called by the firmware. Would be a
# one-line NOLINT at the definition if inline suppressions were in play.
#
# ==========================================================================
# 3. clang-analyzer-deadcode.DeadStores, falcon-core/src/luks/luks.c (1 entry)
# ==========================================================================
#
# OPEN FINDING, baselined so the gate is usable, NOT a false positive.
#
# In the digest loop, `matched = 1` at luks.c:599 is genuinely dead: every
# path after it returns from inside the loop, and every `continue` is above
# it. So the loop's only exit to the tail is the `r == 0` break, where matched
# is still 0, and the tail `return matched ? LUKS_ERR_NOKEY : LUKS_ERR_CORRUPT`
# can only ever yield LUKS_ERR_CORRUPT.
#
# cppcheck agrees independently (unreadVariable at the same line, visible with
# CPPCHECK_ENABLE=style). Not a memory-safety problem: the reachable answer,
# "no digest references this keyslot" -> LUKS_ERR_CORRUPT, is a defensible
# one. But the two-way tail says the author expected a second outcome, so
# either the variable and the ternary should go, or a case that should return
# LUKS_ERR_NOKEY is currently returning something else. Needs an owner
# decision; remove this entry once it is resolved.
#
# ==========================================================================
# 4. falcon-winjump/src/winjump.c, Win32 API idioms (8 entries)
# ==========================================================================
#
# This is the only file in the tree that targets Windows userland rather than
# EFI or Linux, and every hit is the Windows API's conventions, the freestanding
# build's requirements, or an analyzer limit, rather than anything about our
# code. It is analysed at all because it parses a config file and a drive
# listing; that part gets the same scrutiny as the rest of the tree.
#
#   bugprone-reserved-identifier, _WIN32_WINNT and _UNICODE (2 entries).
#       Both are reserved to the implementation and both are REQUIRED to be
#       defined by the translation unit before <windows.h>: they are how the
#       SDK is told which API level and which character width to expose.
#       There is no non-reserved spelling.
#
#   cppcheck uninitvar, "Uninitialized variable: d" in memset (1 entry).
#       winjump links no C runtime and defines memset itself; cppcheck
#       applies its library model of the standard memset (which writes d
#       and so must receive an initialised pointer) to our definition of it,
#       and reports the parameter as uninitialised inside its own body.
#       First seen 2026-09-26, when the gate was made to build before
#       analysing: cppcheck had been loading no compile database and
#       reporting nothing.
#
#   bugprone-reserved-identifier, __stack_chk_guard and __stack_chk_fail
#       (2 entries). winjump links no C runtime (-nostdlib; see the head of
#       winjump.c), so the two symbols -fstack-protector-strong calls into,
#       which libssp would otherwise provide, are defined in the file itself.
#       Their names are the compiler's, not ours; there is no other spelling
#       it will call.
#
#   optin.core.EnumCastOutOfRange, ATTACH_VIRTUAL_DISK_FLAG (1 entry). The
#       flags are OR-ed, READ_ONLY (1) | PERMANENT_LIFETIME (4) = 5, and the
#       enum declares no enumerator for the combination, as flag enums never
#       do. Both flags are mandatory for an ISO attach (DESIGN Section 6.3),
#       so the value is exactly right and the check simply does not model
#       bitmask enums.
#
#   clang-analyzer-core.uninitialized.Assign, jwjoin (1 entry). The driver
#       fallback's write_driver names a temp path with GetTempPathW, whose
#       output buffer the analyzer does not model as written, then joins onto
#       it; the analyzer traces the "uninitialized" buffer into jwjoin's copy.
#       GetTempPathW writes the buffer whenever it returns non-zero, which is
#       the only path that reaches the join. An API-output modelling limit.
#
# ==========================================================================
# 5. -Wanalyzer-out-of-bounds in wbuf_ucs2 (0 entries: a scoped pragma)
# ==========================================================================
#
# apps/stick/efi_main.c, the copy loop behind every menu tag:
#
#     while (*s != 0 && w->len + 1 < w->cap)
#         w->buf[w->len++] = *s++;
#
# The analyzer reports a two-byte read past the end of the literal L"[" in
# tags_build. It cannot happen: *s is tested before each read and s advances
# only inside the body, so a two-unit literal is read exactly twice, at [0]
# and at the terminator. The write is bounded by the same condition, which
# leaves w->len <= cap - 1 for the terminating store.
#
# It is a path-length artifact. The trace gcc prints is sixty steps long,
# from efi_main through banner_init, scan_all_volumes, targets_build,
# probe_entries, out_dec, payload_survey and tags_build before it reaches
# the loop, and the analyzer has lost the literal's extent by the end of it.
# It appeared when the survey moved into falcon-core (media/survey.c) and
# the call graph in front of the loop changed shape; the loop itself has not
# been touched. When the rows came to be probed lazily (2026-09-28) the one
# entry became seventeen, one per path into the loop, so the finding is now
# silenced where it arises, with a scoped pragma on wbuf_ucs2 (the pattern
# falcon-cli/src/common/proc.c uses), rather than counted here.

# ==========================================================================
# 6. bugprone-narrowing-conversions (15 entries)
# ==========================================================================
#
# One pattern, repeated: an ASCII case fold written as
#
#     (char)(c + ('a' - 'A'))
#
# in bootcfg.c, isoprobe.c, payload.c, manifest.c, blesslist.c, udf.c,
# x509.c, inspect.c and main.c. The cast is already explicit and the operand
# is already known to be an upper-case letter, so the value is in range by
# construction; the check objects to int arithmetic reaching a char at all.
# LLVM 19 reports it, LLVM 22 does not, which is most of why this baseline
# is larger than the one it replaced.
#
# ==========================================================================
# 7. clang-analyzer-core.NullDereference, falcon-core/src/media/bootcfg.c
# ==========================================================================
#
# `buf = p->scratch + p->used` then `buf[n] = '\0'`. The analyzer cannot
# prove the caller's scratch pointer is non-null and so treats the offset as
# a null dereference. Every caller in the tree passes a real array; the
# parser never allocates and never takes ownership of one, which is the
# convention DESIGN Section 9 sets for the whole of falcon-core.
#
# ==========================================================================
# 8. -Wanalyzer-use-of-uninitialized-value, sha256.c and sha512.c
# ==========================================================================
#
# The message schedule `w[]` is filled by a loop immediately before it is
# read, and gcc's analyzer will not follow the loop far enough to see it.
# The same false positive appeared in falcon-core/src/fs/fat.c while it was
# being written; there it was cheaper to write the code so the analyzer
# could follow it than to baseline it. Here the loops are the published SHA
# schedules and are not worth rearranging around a tool.
